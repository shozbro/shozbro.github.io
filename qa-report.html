Scope and environment

browser
Chromium 141 (Playwright 1.56), headless, Linux
build
Static index.html served from a local web server, web fonts served locally to match production
layouts
Vertical below 1024 px wide or 700 px tall; horizontal travel above. Tested at 320, 360, 390, 414, 768, 900, 960, 1023, 1024 px wide and at 1280x720, 1366x768, 1440x900, 1536x864, 1920x1080, 2560x1440
themes
Light, dark, system preference and manual toggle
tools
Playwright, axe-core 4.10 (WCAG 2.1 AA and best practice), html-validate 9
emulation
Touch and mobile, reduced motion, blocked storage, refused clipboard, failed web fonts, trackpad sideways swipes, live window resizing

Not covered

  • Firefox and Safari engines. Only Chromium was available in the test environment.
  • Physical phones and real screen readers. Accessibility was checked with axe-core and keyboard tests only.
  • The live GitHub Pages deployment and slow network conditions.

Test script fixes

Some failures across the runs were mistakes in the test code, not the site. They were fixed in the suite and are not counted as product defects.

  • TC-15 Clicked an already-caught bug without forcing, which Playwright correctly refused (the button is aria-disabled). Fixed with force: true.
  • TC-23 Read the PDF response body after closing the browser context. Reordered.
  • TC-38 Counted hidden elements as tab stops and then flagged the document body. Loop now stops when focus leaves the page.
  • TC-03 Flagged a screen-reader-only element as breaking the gutter. Excluded .sr-only.
  • TC-45 Its wait was already true at the moment of the click, so it measured nav travel mid-flight after a fixed delay. Now waits until the page has arrived.
  • TC-06, TC-45 Expected a nav link to the featured report section. The header link opens the report page itself, and the section is reached from the intro, which TC-60 now covers.
  • TC-03 (again) The gutter check still flagged screen-reader-only headings, not just paragraphs. It now skips every .sr-only element.
  • TC-48 Expected scrollIntoView to make the target's panel current. The browser correctly stops once the element is visible at the right edge. Now checks visibility and sync.
  • TC-10 Still expected the old cobalt dark background after the palette was restored. Updated to the slate value.
  • TC-15 Clicked the footer's hidden bug from the start of the page. The footer is now shown only at the end of the travel, so the test travels there first, as a visitor would.
  • TC-48 Required the scrolled-to heading to sit inside the screen to the exact pixel. The browser rounds scroll positions to whole pixels, so it now allows 1 px.
  • TC-76 Compared the panel top with the header's outer edge, which includes its 1 px border. Now allows that border.
